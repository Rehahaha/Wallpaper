## 0. 决策记录（ADR）

| 编号 | 决策点 | 结论 | 理由 |
|---|---|---|---|
| ADR-001 | 首发平台 | Windows 10 1903+ / Windows 11 | 桌面动态壁纸是 Windows 强需求；macOS / Linux 后置 |
| ADR-002 | 技术栈 | C# + WPF（.NET），单进程 + Win32 互操作 | 挂载桌面层只能走 Win32；C# 开发效率高、包体小、功耗可控 |

| ADR-004 | 产品名 | **Wallpaper** | 用户指定 |
| ADR-005 | .NET 版本 | .NET 10 LTS（代码保持 8.0 兼容，不用 10 专属特性） | .NET 8 支持 2026-11-10 结束；10 为 LTS 至 2028-11 |
| ADR-006 | 素材 4K | 支持最高 4K，按硬件能力自适应降级 | 用户素材含 4K |

## 1. 背景与目标

### 1.1 背景
用户从网上下载了动态壁纸素材（mp4 / webm 视频），但系统只支持静态图片设为桌面背景。现有第三方动态壁纸软件要么体量庞大、要么捆绑内容、要么需要订阅，只是想"把我这段视频放到桌面上播放"这件事反而很重。

### 1.2 产品目标
做一个**轻量、本地、不联网也能用**的小工具：选中一个本地视频 → 一键设为动态桌面壁纸 → 桌面图标照常使用。

### 1.3 MVP 成功标准（验收线）
1. 从打开 App 到视频出现在桌面上，**不超过 3 次点击**。
2. 1080p / 30fps 视频循环播放时，**CPU 占用 < 15%**（硬件解码可用时），**内存 < 300MB**。
3. 壁纸位于桌面图标**下方**，不遮挡图标点击，不干扰任务栏与开始菜单。
4. 托盘退出后，桌面**恢复为系统原来的静态壁纸**（不留残影、不留黑屏）。
5. 连续播放 8 小时无崩溃、无内存持续增长。

### 1.4 非目标（MVP 阶段明确不做）
- 不做素材商店 / 在线下载 / 账号系统。
- 不做视频剪辑、滤镜、特效。
- 不做网页壁纸（HTML/WebGL）。
- 不做多显示器独立壁纸（v1.1 再做）。
- 不做声音输出（默认静音，v1.1 再加音量控制）。

## 3. 功能需求

优先级定义：**P0 = MVP 必须**，**P1 = 首个正式版**，**P2 = 后续迭代**。

### FR-1 视频导入（P0）
- 支持"选择文件"与"拖拽文件到窗口"两种入口。
- 支持格式：**mp4（H.264）**、**webm（VP8/VP9）**；gif 转 mp4 不做（P2）。
- 单文件上限 2GB，超出给出明确提示。
- 不支持的格式：提示"当前仅支持 mp4 / webm"，不崩溃。

**验收**：拖入 `test.mp4` → 列表出现该素材并显示缩略图 → 点击"设为壁纸" → 桌面开始播放。

### FR-2 壁纸播放（P0）
- 视频窗口挂载到桌面图标**下方**（Windows `Progman` / `WorkerW` 方案）。
- 默认**循环播放**、**静音**。
- 窗口不出现在 Alt+Tab 与任务栏中。
- 关闭壁纸后，桌面回到原样。
  - **实现方式变更（M1）**：采用**覆盖式**方案 —— 不修改系统壁纸设置，只在桌面层叠一个 mpv 渲染窗口。停止壁纸 = 销毁该窗口，系统壁纸毫发无损，"恢复原壁纸"这条风险直接消失。

**验收**：设置壁纸后，按 Win+D 显示桌面 → 视频仍在播放；点击桌面图标可正常选中与打开；Alt+Tab 列表中看不到本 App 的播放窗口。

### FR-3 画面适配（P0）
- 三种模式：**填充（cover，默认）**、**适应（contain，留黑边）**、**拉伸（stretch）**。
- 视频宽高比与屏幕不一致时，默认按填充并居中裁切。

**验收**：4:3 视频在 16:9 屏幕上，切到"适应"后左右出现黑边、画面不变形。

### FR-4 播放控制（P0）
- 暂停 / 继续。（实现：mpv JSON IPC `set_property pause`，实测暂停时画面帧差 0%、继续后恢复 13%，无需重启进程）
- "关闭壁纸"（停止播放并恢复静态壁纸）。
- 切换素材（选中列表项 → 立即替换当前壁纸）。

### FR-5 素材库（P0）
- 列表展示：缩略图、文件名、时长（由 mpv `observe_property duration` 回填）、添加时间。
- 标记当前正在使用的一项。
- 支持移除素材（只从库中移除，**不删除本地文件**，需二次确认）。

### FR-6 状态记忆（P0）✅ 已实现
- 记住上次使用的素材与适配模式，下次启动自动恢复壁纸。
- 开机自启：默认**关闭**，界面勾选「开机自动启动（最小化到托盘）」即可开启；写 HKCU Run 项，带 `--minimized` 静默启动。（已完成）

### FR-7 托盘与退出（P0）
- 关闭主窗口 = 收到托盘（不退出进程）。
- 托盘菜单：显示主窗口 / 暂停 / 继续 / 关闭壁纸 / 退出。
- 退出时确保恢复原壁纸并释放进程。

### FR-8 全屏应用自动暂停（P1）✅ 已实现
- 检测到全屏窗口（游戏、全屏视频）时自动暂停，退出后恢复。
- 实现：`GetForegroundWindow` + `MonitorFromWindow`/`GetMonitorInfo` 比对窗口矩形与显示器矩形，容差 2px；
  进入/退出各需连续 2 次命中（防抖动）；桌面、任务栏、锁屏（`Windows.UI.Core.CoreWindow`）与本进程窗口不计入。
- 与手动暂停互不干扰：用户手动暂停后，进出全屏不会擅自恢复。
- 开关默认开启，可在主界面取消勾选。

### FR-9 电源策略（P1）
- 电池供电时降低帧率或暂停，可配置。

## 5. 技术方案（已定，见 ADR-002 / ADR-003）

### 5.1 整体架构

```
Wallpaper.sln
├── src/Wallpaper.App          WPF 主界面（素材库、设置、托盘）
├── src/Wallpaper.DesktopHost  Win32：WorkerW 挂载 + 播放子窗口
├── src/Wallpaper.Player       libmpv 封装（P/Invoke）
└── src/Wallpaper.Core         配置、素材库、缩略图、日志
```

关键点：**播放窗口不是 WPF 控件**。DesktopHost 创建一个普通 Win32 子窗口（挂在 `WorkerW` 下），把该句柄通过 `--wid` 交给 mpv 渲染。既避开 WPF 视频 airspace 限制，也让壁纸层零 UI 开销。

### 5.1.1 渲染必须走 GPU 交换链（M0 实测结论，重要）

实测数据（Windows 11 26200 / Intel 核显 / 2560x1600 @200%）：

| 渲染方式 | 是否上屏 | 说明 |
|---|---|---|
| WPF/GDI 自己画（`FillRect`） | ❌ 不可见（差异 0%） | 窗口确实在画（`WM_PAINT` 计数=3），但 `Progman` 带 `WS_EX_NOREDIRECTIONBITMAP`，没有 DWM 重定向表面，GDI 内容不参与合成 |
| mpv `--wid=WorkerW`（D3D11 交换链） | ✅ 可见（差异 96.1%） | D3D/Composition 内容正常合成 |
| mpv `--wid=<我们的宿主窗口>` | ✅ 可见（差异 31.8%，彩条清晰） | **MVP 采用这条路径** |

**结论**：不要在壁纸层用 GDI/WPF 绘制任何东西（包括纯色底、遮罩、字幕）。所有画面必须由 mpv 的交换链输出；要画 UI 只能在它之上叠独立窗口，或者干脆不画。

### 5.2 关键技术点
1. **桌面层挂载**：向 `Progman` 发送 `0x052C` 消息生成 `WorkerW`，将播放窗口 `SetParent` 到该窗口下，使其位于图标之下。
   - **实测结论（Windows 11 build 26200）**：壁纸层是 **`Progman` 的子窗口 `WorkerW`**（全屏、无 `SHELLDLL_DefView` 子窗口），**不是** 网上教程常见的"顶层 WorkerW 兄弟窗口"。老式顶层方案在此版本会误判到任务栏的 WorkerW。代码已做成「先找子窗口，再退回顶层」的双分支。
2. **窗口样式**：`WS_EX_TOOLWINDOW | WS_EX_NOACTIVATE`，隐藏任务栏按钮与 Alt+Tab 项。
3. **解码**：优先 D3D11 硬件解码；软解兜底。
4. **全屏检测（P1）**：`GetForegroundWindow` + 窗口矩形与显示器矩形比对，排除桌面自身。
5. **恢复原壁纸**：设置前记录当前壁纸路径（`SystemParametersInfo(SPI_GETDESKWALLPAPER)`），退出时回写；纯色 / 幻灯片模式需单独处理。

### 5.3 主要风险
| 风险 | 影响 | 对策 |
|---|---|---|
| Windows 更新导致 WorkerW 行为变化 | 壁纸不显示或盖住图标 | 多分支尝试 + 启动自检 + 回退静态模式 |
| 第三方壁纸程序（如 Lively）抢占桌面层 | 我们的画面被整块盖住 | 启动时检测 `Progman` 下是否已有其他渲染子窗口，提示用户关闭 |
| mpv 分发带来的 GPL 义务 | 闭源/商用受限 | 见待确认问题 #6：内置 mpv / 让用户自装 / 换 Media Foundation |
| 显卡驱动差异导致黑屏 | 用户以为程序坏了 | 解码失败自动降级软解并提示 |
| 全屏检测误判（浏览器 F11 等） | 壁纸忽停忽播 | 可关闭的开关 + 延迟判定 |
| 杀毒软件误报（挂载桌面窗口） | 安装失败 | 正式版代码签名 |

### 5.4 4K 素材策略（ADR-006）

测试机为 **Intel 核显**（Intel(R) Graphics），4K 是明显的性能边界：

| 环节 | 策略 |
|---|---|
| 解码 | 优先 `hwdec=d3d11va`（D3D11VA / QSV）→ 失败降级 `dxva2` → 最后软解 |
| 渲染 | **只按显示器实际分辨率渲染**；4K 素材在 1080p 屏上由 GPU 缩放，不输出 4K |
| 帧率 | 4K60 素材默认限到 30fps 输出（设置可改） |
| 预检 | 首次导入 4K 素材时做 2 秒解码压测，自动选「流畅 / 省电」预设 |
| 兜底 | 无硬解能力时，4K 降到 1080p 渲染并提示一次 |

**性能预算**：4K30 硬解 CPU < 25%、GPU < 40%、显存 < 500MB。

## 6. 本地数据结构

```
%APPDATA%\VideoWallpaper\
├── config.json        # 设置与素材库
├── thumbs\            # 缩略图缓存
└── logs\              # 运行日志（保留 7 天）
```

`config.json` 示例：

```json
{
  "version": 1,
  "activeId": "a1b2c3",
  "fitMode": "cover",
  "muted": true,
  "autostart": false,
  "library": [
    {
      "id": "a1b2c3",
      "path": "D:\\wallpapers\\city.mp4",
      "name": "city.mp4",
      "durationSec": 24,
      "thumb": "thumbs\\a1b2c3.jpg",
      "addedAt": "2026-10-28T11:00:00+08:00"
    }
  ]
}
```

说明：素材库只存**路径引用**，不复制视频文件（节省磁盘）；文件被移动或删除时列表标灰并提示"文件已丢失"。

## 7. 交互流程（核心三步）

```
[打开 App] → [拖入 / 选择视频] → [点击"设为壁纸"] → 完成
                                      ↓
                         关闭主窗口 = 收进托盘，壁纸继续运行
```

主窗口布局（MVP 单页）：
- 顶部：标题 + 设置入口
- 左：素材列表（缩略图网格）
- 右：预览 + 适配模式选择 + 「设为壁纸 / 关闭壁纸」
- 底部：状态栏（当前素材、解码方式、占用）

### 9.1 移动端可行性（提前对齐预期）

| 平台 | 能否设视频壁纸 | 实现方式 | 结论 |
|---|---|---|---|
| Android | 能 | `WallpaperService` + ExoPlayer，原生模块 | v2.x，需原生重写 |
| iOS | **不能** | 系统只允许 Live Photo 作为**锁屏**动态壁纸，主屏只能静态图 + 组件 | iOS 版定位为「素材管理 / 预览 / Live Photo 制作」 |

**结论**：跨平台不存在"一套代码搞定"。可共享的只有素材格式、配置结构、UI 规范；播放引擎必须按平台原生实现。因此 MVP **不做跨端抽象层**，避免过早耦合。

## 10. 待确认问题

1. **H.265 / HEVC**：4K 素材常见 h265，MVP 是否要支持？（mpv 能解，但 Windows 需装 HEVC 扩展或走软解，影响性能。建议 MVP 先只保 h264 + 自动降级）
2. **素材存放**：只引用原路径（省磁盘，移动文件会丢失）vs 导入时复制到应用目录（安全，占空间）。建议 MVP：只引用 + 丢失提示。
3. **开机自启**：默认开还是关？（建议默认关）
4. **最低 Windows 版本**：卡 1903 还是放宽到 1809？
5. **分发形式**：绿色便携 exe 优先，还是直接做安装包（Inno Setup / MSIX）？
